# 2026-11-11 拆分 main.swift 为多文件结构

> **历史决策记录**：描述当时的一轮改动与取舍。当前实现以 [ARCHITECTURE.md](../../ARCHITECTURE.md) 为准。

## 目标

纯结构重构，行为完全不变。对应上轮评审的优先级 1。

## 动机

- `Sources/main.swift` 1798 行，塞了 19 个类型 + 27 个全局函数；swiftui-pro 要求「按类型拆到不同 Swift 文件」。
- MARK 分区名失真：`// MARK: - 配色` 下挂 547 行，实际是全部 SwiftUI 视图；`SwiftUI 视图` 分区只有 11 行，导航失效。
- `main.swift` 顶层可执行代码与库代码混放。Swift 的全局变量按源码顺序初始化，历史上 `--selftest` 因此 segfault，文件头还留着专门注释规避。拆文件可根除该陷阱。
- `build.sh` 硬编码只编译 `main.swift`，无 `Package.swift` / `Tests/`。

## 关键约束与处理

- **顶层代码只能在 main.swift**：`--version-check` / `--hotkey-check` / `--selftest` 三个分支与 `NSApplication.shared` 启动代码全部收进 `main.swift`，其余文件只放声明。
- **顶层 `private` 声明**：`QUOTES` 与其使用者 `workingQuote` / `computeState` 同放 `Model/Time.swift`，保持 `private`；3 个热键全局变量与 `registerGlobalHotKey` 同放 `App/HotKey.swift`。未改动任何访问控制。
- 每个文件按需补 imports（AppKit / SwiftUI / Combine / ServiceManagement / Carbon / Foundation）。
- `build.sh` 改为 `find Sources -name '*.swift' | sort` 收集全部文件编译；Swift 以文件名识别 `main.swift` 为入口，传入顺序无关。
- 拆分脚本先做**区间覆盖检查**：原 7..1798 行每行恰好归入一个文件，无重无漏；1–6 行原 imports 丢弃（各文件重新声明）。

## 验证

- 14 个文件一次编译通过，无 `private` / import 报错。
- `--version-check` / `--hotkey-check` / `--selftest`（38 项）全过；**`--selftest` 不再 segfault**，初始化顺序坑消除。
- `build.sh` 全链路（图标 / 编译 / 签名 / 三项自检）通过；签名有效；启动后菜单栏项、悬浮窗、popover 打开/关闭均正常，无崩溃，用户设置保留。
- 悬浮窗高度 83 → 86，是上轮 Dynamic Type 字号调整后 `resizePanelToFit()` 的自适应结果，符合预期。
