# 2026-11-11 悬浮窗统一、Dynamic Type 与登录自启状态同步

> **历史决策记录**：描述当时的一轮改动与取舍。当前实现以 [ARCHITECTURE.md](../../ARCHITECTURE.md) 为准。

## 目标

1. 悬浮窗与设置面板统一视觉语言（白底 + 语义色 + 一致字号层级）
2. 支持 Dynamic Type，不再写死 9.5 / 10 / 11pt 小字
3. 「登录时启动」开关与系统真实状态同步

## 现状问题

- 设置面板已是 Cursor 风格白底分组卡片，悬浮窗仍是 `.ultraThinMaterial` + 9.5pt 小字 + 🕕 emoji，在蓝色壁纸上会透色，视觉断层明显。
- `.system(size:)` 固定字号不受辅助功能字号影响，且多处低于 12pt 可读性下限。
- `launchAtLogin` 只存本地偏好；用户在「系统设置 → 通用 → 登录项」手动删掉后，app 里的开关仍显示开。

## 方案

### 组件（任务 1 + 2）

- `PanelRoot` 背景由 `.ultraThinMaterial` 改为 `PanelColor.background`（浅色纯白 / 深色 `#1C1C1E`），保留细边框。
- 小字全部换成语义字体：标题 `.footnote`、说明/百分比 `.caption`、语录 `.footnote`；收缩按钮图标用 `.caption`。
- 大号倒计时数字（30 / 42pt）用两个 `@ScaledMetric(relativeTo:)` 包装，跟随 Dynamic Type 缩放；`DigitsText` 保留 `.minimumScaleFactor(0.7)` 兜底。
- 收缩态的 🕕 emoji 换成 `Image(systemName: "clock")` SF Symbol（emoji 只保留在状态文案里作品牌趣味）。
- `st.sub` 由 `lineLimit(1)` 放宽到 2 行 + `fixedSize(horizontal: false, vertical: true)`，大字号下换行而不是截断；高度由已有 `resizePanelToFit()` 重算。

### 数据流（任务 7）

- `Store.syncLaunchAtLogin()`：读 `SMAppService.mainApp.status`，`.enabled` 视为已注册；否则回退检查 `~/Library/LaunchAgents/com.rumor.offwork-countdown.plist` 是否存在。任一为真即视为开。
- 调用时机：`applicationDidFinishLaunching` 一次，以及每次打开设置面板时（用户可能刚在系统设置里改过）。
- 纯函数 `launchAtLoginEnabled(systemRegistered:plistExists:)` 供回归自测。
- 同步只读系统状态，不尝试注册/注销，避免副作用。

### 错误处理

- 注册失败仍走 `timeError` 统一横幅，开关保持旧值；同步失败（plist 不可读）按未启用处理。
- 同步可能改写 `prefs.launchAtLogin`，触发 `@Published` → `save()` / `applyPrefs`，与启动时已有的 `applyPrefs` 幂等。

### 测试

- 新增 1 项纯函数自测（37 → 38 项）。
- `xcrun swiftc` 编译无警告；`--selftest` 全过；离屏渲染确认悬浮窗白底与字号；启动 + 打开面板无崩溃、设置不丢失。

## 取舍

- 本轮不做：Reduce Motion、退出确认、工作日选中态加勾、节假日内置数据（均在上轮清单中但本轮未点名）。代码拆分随后单独完成，见 `docs/plans/2026-11-11-多文件结构拆分-design.md`。
- 悬浮窗固定宽度 200 / 300 保留（紧凑定位），仅让高度随内容自适应。
- 不在本仓库 `git commit`（Obsidian 库位于更大的仓库内，推 GitHub 需用户另行确认）。
