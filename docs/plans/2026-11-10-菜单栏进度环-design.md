# 菜单栏进度环设计

- 日期：2026-11-10
- 状态：**已实现**（2026-11-10）
- 说明：**历史决策记录**。文中部分早期方案与实测数字已被后续迭代取代；当前实现以 [ARCHITECTURE.md](../../ARCHITECTURE.md) 为准，下方矛盾段落已标注。
- 关联项目：下班倒计时 macOS 应用（`其他/OffWorkCountdown/`）

## 目标与约束

解决的问题：菜单栏占用空间偏大、图标与相邻 app 的图标尺寸/风格不一致、三态图标只能表达「还没下班」而看不出还剩多久。

约束：

- 菜单栏**不显示任何数字或文字**
- 项宽 ≤ 20pt（当前 26pt）
- 保持现有交互：悬停 tooltip、左键开面板、右键开菜单、隐身
- 保留「完整 / 精简」两档文字模式，行为不变
- 不联网、不新增依赖、不新增数据源

## 视觉规格

- 14pt 直径细圆环，线宽约 2pt，在 20pt 项宽内居中
- 自绘图形，单色模板色跟随系统深浅模式（`NSColor.controlTextColor`）
- 从 12 点方向顺时针填充，比例 = `st.progress`（今日净工作进度，已含午休扣除），clamp 到 0–1
- 直径、线宽、视觉重量全部可控，不再受 SF Symbol 内在尺寸约束（这是此前多次调 `NSImage.size` 无效的根因）

## 状态映射（只靠形态，不用颜色）

| 状态 | phase | 形态 |
| --- | --- | --- |
| 等下班 | `.working` / `.before`（含午休） | 浅灰底环 + 实色进度弧；午休时弧末端加一个小圆点表示暂停 |
| 已下班 | `.off` | 满环 + 中心小实心点（完成标记） |
| 休息日 | `.rest` | 8 段短弧组成的虚线空环 |
| 隐身 | 任意 | 极淡空心圈，不暴露状态 |

形态编码为主：色弱友好、自动适配深浅模式、视觉更克制。颜色只作为**补充的进度阶段提示**（见「补充设计：进度阶段色点」），不取代形态编码。

## 架构与数据流

- 新增 `RingStatusView: NSView`（约 80 行），只负责绘制
- 三档**统一使用 `statusItem.button`**。`menuStyle == 2` 时把 `RingStatusView` 作为 button 的子视图（`hitTest` 返回 nil 让鼠标事件穿透到 button），项宽由 `menuPercent` 决定（开启 58pt / 关闭 20pt）；其余两档直接用 button 的 title。不再使用已废弃的 `statusItem.view`
- `AppDelegate.tick()` 每 0.5s 把 `(phase, progress, isStealth)` 写入 view，**仅值变化时** `needsDisplay = true`（进度一分钟才动一点，避免空转）
- 绘制参数抽成纯函数 `ringSegments(phase:progress:)`，便于断言

## 交互

- ~~自绘 view 没有系统按钮行为：重写 `mouseDown` / `rightMouseDown`，转发到现有「左键开面板、右键开菜单」逻辑~~ **（已废弃：最终改用系统 `NSStatusBarButton` + `hitTest` 穿透，见下条）**
- `toolTip` 保留完整信息（如「距离下班还有 2:32:30」）
- 点击高亮：**由系统 `NSStatusBarButton` 原生绘制**（颜色 / 圆角 / 尺寸全部自动与相邻菜单栏项一致）。`AppDelegate` 实现 `NSPopoverDelegate`，在 `popoverDidShow/DidClose` 调用 `button.highlight(true/false)` 让面板打开期间保持高亮
  - **走过的弯路**：最初用 `statusItem.view` 自绘，系统完全不接管高亮；先试 `controlTextColor` 淡底得到 `(64,135,195)` 偏灰，又试硬编码亮蓝 `(52,158,239)` 逼近系统 `(55,160,243)`——都是「仿」，永远对不齐。最终按用户提示回到系统 button，删掉全部自绘高亮与 `mouseDown` 接管代码（`hitTest` 穿透即可），编译的 `statusItem.view` 废弃警告也随之消失
- 深浅模式：`viewDidChangeEffectiveAppearance()` 触发重绘

## 兜底与边界

- `NSStatusItem.view` 属较老 API；若某版 macOS 未渲染，回退到现有 SF Symbol 三态图标（旧路径保留不删）
- `progress` clamp 0–1；未知 phase 只画底环
- `currentIconName` 缓存保留给文字档的隐身图标（环模式不使用）；`ringUnavailable` 仅在 `statusItem.button` 创建失败时把有效档位降到 1，避免每帧反复重建

## 补充设计：进度阶段色点（2026-11-10 追加）

用户要求右下角加一颗按进度变色的点。

- **位置**：环右下角（约 4–5 点方向，`dist = r + 1.5`），直径 6pt（半径 3.0），故意压住环右下角一小段；不增加项宽。几何抽成 `ringDotGeometry(ringCenter:ringRadius:)`，自测验证在 20×22 视图内不越界且与环外缘重叠
- **颜色**：四段低饱和纯色，到边界直接切换（不渐变）
  - 0–25%：绿 `#5BAE84`
  - 25–50%：黄 `#DFC25E`
  - 50–75%：橙 `#E0A355`
  - 75–100%：正红 `#FF2D2D`（R=255、G=B=45，饱和度 100%，不偏橙不偏粉；前三档保持低饱和，红色单独提亮作醒目警示）
- **显示范围**：仅 `.working` / `.before`；`.off` / `.rest` / 隐身不显示，避免下班后还挂着红点像警告
- **实现**：抽成纯函数 `ringDotColor(phase:progress:isStealth:) -> RingDot?`，返回 RGB 分量；`RingStatusView.draw` 末尾绘制
- **兼容性**：环本身仍单色、形态编码不变，色弱用户不受影响
- **测试**：6 项断言覆盖四档颜色、边界（0.249/0.25/0.499/0.5/0.749/0.75）、clamp 与状态隐藏，另有 1 项几何不越界

## 补充设计：菜单栏百分比文字（2026-11-10 追加）

参考相邻 app 的「图标 + 百分比」样式，在进度环右侧加一个百分比。

- **显示**：`menuPercentText(progress:isStealth:)` 返回 `41%` 形式的单色文字，用 `NSFont.systemFont(ofSize: 13.5, weight: .regular)`、`NSColor.controlTextColor` 自动适配深浅模式；环线宽从 2pt 加粗到 2.5pt（图标填充密度 20% → 约 25%，更接近相邻实心图标的 30%）；隐身时文字返回 nil
  - **字重校准**：截图量化显示相邻 app 文字笔画密度 33%、我们一度用 `.bold` 达 40.7%（偏粗、小尺寸下发虚）。实测各字重墨量 regular 100% / medium 108% / semibold 116% / bold 126%，取 `.regular`（约 32%）最贴近；同时文字 y 坐标 `round(...)` 取整，消除半像素绘制导致的发虚
- **布局**：环固定在视图左侧 x=10（纯环时正好居中，带文字时靠左）；文字**右对齐**，右边距固定 2pt、`x = round(width - 2 - textWidth)`，y 同样取整，避免半像素发虚。右对齐是为解决「3 字符百分比时右侧堆大片空白」：位数变化时空白移到环与文字之间，右侧始终只有 2pt。`menuPercent` 开启时视图与 `statusItem.length` 为 58pt（容纳 13.5pt 常规体 `100%`：宽 35pt，x=21，21+35=56 ≤ 58），关闭时为 20pt
- **开关**：设置里「菜单栏显示百分比」（仅进度环档可用，其他档 disabled）；`currentPercentShown` 检测变化并重建 `statusItem`，保证宽度即时更新
- **状态**：百分比取 `st.progress` clamp 0–1（休息日 0%、已下班 100%）；隐身时文字留空但项宽不变，避免旁边图标左右跳动
- **测试**：2 项断言覆盖 clamp（42% / 100% / 0%）与隐身隐藏
- **权衡**：开启后项宽从 20pt 增至 58pt，是用户主动要求（与相邻 app 风格统一）；保留开关以便随时回到最省空间的纯环。右对齐 + 58pt 使右侧空白与相邻项一致（实测从 69px 间距降到标准水平）

## 决策记录

- 选「进度环」而非「自绘精致图标」：同时解决宽度与信息量，而不只是换一个更好看的图标
- 选「形态编码为主、颜色为辅」：状态靠形态（色弱友好），颜色只表达工作中进度阶段
- 保留 SF Symbol 回退路径：`ringUnavailable` 在系统 button 创建失败时降级，降低兼容风险
- 高亮采用**系统原生 `NSStatusBarButton`**：点击反馈、颜色、圆角全部交给系统，不再自己仿制（这是最终方案）

## 实现与验证结果

- 自测全过（当时 37 项，现为 38 项）：进度环 clamp / 三态形态 / 隐身降级 / 色点四档绿黄橙正红、边界、状态隐藏、正红不偏粉、放大后几何不越界且压住环 / 百分比 clamp、隐身隐藏、100% 不越界）
- 菜单栏项宽度实测：百分比开启 74px、关闭 36px（回到纯环）
- 与相邻 app 的风格对比（截图量化）：百分比字高 17→约 19px、图标填充密度 20%→约 25%（相邻 30%），整体宽度保持同一量级
- CGWindow 按 PID 实测菜单栏窗口宽度：完整档 95、精简档 58、**进度环 36**（比精简窄 38%）
- 三档切换启动均正常；热键隐身后环仍在、悬浮窗消失，恢复后悬浮窗回来
- 模拟点击进度环 → 弹出设置面板（**当时** 356×566，现为 356×446），Escape 可关闭；系统 button 的点击与 popover 定位链路正常
- 用户原有设置（紧凑模式等）在测试后完整恢复
- 改用系统 button 后编译**不再有废弃警告**；点击 → popover（**当时** 356×586，现为 356×446）→ Escape 关闭链路实测正常，无崩溃
