# 不计入工时的休息时段（通用多段）

> **项目文档 · 描述当前实现**。架构总览见 [ARCHITECTURE.md](../ARCHITECTURE.md)，作息规则见 [作息规则.md](作息规则.md)，周进度见 [周进度.md](周进度.md)。
> 对应源码：`Sources/Model/Prefs.swift`、`Sources/Model/Time.swift`、`Sources/App/Store.swift`、`Sources/UI/MenuView.swift`。

## 目标

把原来「单一午休」泛化成**任意多段不计入工时的休息**：午休、晚饭、下午茶……每段有名称、起止时间、独立开关，可任意增删。进度、倒计时状态、周工时全部按同一套规则扣除。

沿用「配置化、别人也能用」的原则：产品不预置任何时间或段名，全部由使用者配置。旧版本的「午休不计入进度」设置会自动迁移成第一段「午休」。

## 数据模型（`Model/Prefs.swift`）

```swift
struct BreakPeriod: Codable, Equatable, Identifiable {
    var id: String
    var name: String      // 如「午休」「晚饭」，用于状态文案
    var start: String     // "HH:mm"
    var end: String
    var enabled: Bool = true
}
var breakPeriods: [BreakPeriod] = []
```

旧的 `breakEnabled / breakStart / breakEnd` **保留但只用于兼容迁移**：`init(from:)` 里若旧 JSON 没有 `breakPeriods` 键、且 `breakEnabled` 为真，就生成一段 `{ id: "legacy-lunch", name: "午休", start/end 取旧值 }`。之后计算与 UI 只认 `breakPeriods`，旧字段不再读写。

`validated()` 过滤非法段（空 id / 空名称 / 非法 HH:mm）；`end <= start` 允许（视为次日，与跨零点班次一致）。

## 计算（`Model/Time.swift`）

`Shift` 由「一对 break」改为 `breaks: [BreakInterval]`（每段含 `start/end/name`）：

| 成员 | 行为 |
| --- | --- |
| `breakLength` | 所有段时长之和 |
| `totalWork` | `max(0, 下班−上班−breakLength)` |
| `breakElapsed(at:)` | 累加各段中「已过去」的部分 |
| `currentBreak(at:)` | 返回当前所处段（带名称） |
| `inBreak(_:)` | `currentBreak != nil` |

`dayShift(_:_:)` 为每个 `enabled` 的段：

1. 用 `align` 把起止对齐到班次内部（跨零点班次的休息可能落在凌晨）
2. **裁剪到 `[班次开始, 班次结束]`**：`cs = max(段开始, 班次开始)`、`ce = min(段结束, 班次结束)`。所以周五 17:30 下班时，18:00 的晚饭段自然不生效；临时改成 18:10 下班则只扣 18:00–18:10
3. 按开始时间排序后**合并重叠段**，避免同一分钟被扣两次
4. 只有 `ce > cs` 才计入

## 状态与文案（`computeState`）

休息中时标题为 `休息中（{段名}）🍚`、语录 `休息中，先别看倒计时 🍚`、菜单 `🍚 休息中`；`sub` 显示「已扣 N 段休息」（N 为启用段数）。倒计时继续走，和原来午休的行为一致。

## 周进度联动

`weekTargetSeconds` / `weekWorkedSeconds` 都走 `dayShift` 的 `totalWork` / `breakElapsed`，因此多段休息会**自动**同时扣减周目标和周累计净工时，无需单独改周进度代码。

## 界面（「作息」Tab）

独立卡片「不计入工时的时段」：

- 列出每段：开关（复选框）+ 名称 + 起止摘要 + 删除；下一行两个时间选择器可改起止
- 「添加时段」折叠表单：名称 + 起止时间
- 默认空时显示说明文字；段数多时卡片自然变高，由 ScrollView 承担滚动

## 兼容与边界

- 旧配置迁移为「午休」段，用户现有 12:00–14:00 不会丢；迁移后只要有过一次设置变更就会写回 `breakPeriods`，重启不再重复迁移
- 用户手动删掉所有段后重启也不会被旧字段复活（JSON 里已有 `breakPeriods` 键）
- 禁用段不生效；段完全落在班次外不生效；重叠段合并
- `breakEnabled` 为假且无新字段的旧配置 → 空列表，行为与旧版一致

## 验证

`--selftest` 72 项，其中与休息段相关的：两段扣减、`currentBreak` 名称、`breakElapsed` 累加、重叠合并、裁剪到班次、禁用段、旧配置迁移、周目标扣除所有段，以及原有「午休扣减进度 / 午休中状态」用例。构建后离屏渲染确认「作息」Tab 含 2 段休息时布局完整、底栏可见。
