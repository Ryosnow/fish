# 作息规则（通用配置化）

> **项目文档 · 描述当前设计**。架构总览见 [ARCHITECTURE.md](../ARCHITECTURE.md)，界面见 [界面与可访问性.md](界面与可访问性.md)。
> 对应源码：`Sources/Model/Prefs.swift`、`Sources/Model/Time.swift`、`Sources/App/Store.swift`、`Sources/UI/MenuView.swift`、`Sources/Tests/SelfTest.swift`。

## 设计原则

**零硬编码时间、零预设星期**。产品只提供一套通用规则机制：具体时间、哪天例外、常用方案全部由使用者配置。任何人的固定班、轮班、临时早下班都只是这套机制的实例，不是特例。

早期讨论里出现过「写死 19:40 / 18:40 / 17:30 快捷按钮」的想法，因只适用于一个人而被否决。

## 两个概念

| 概念 | 说明 |
| --- | --- |
| `WorkSchedule`（作息方案） | `id` + `name` + `start` + `end`，用户自己命名的模板，如「常规 10:00–19:40」。数量不限，可增删改。**只是模板**，不参与时间计算 |
| 三类绑定规则 | 全局默认（现有 `start` / `end`）、按星期、按日期 |

规则里存的是**作息值**（`DaySchedule`）而不是方案 id：选方案时把值拷进规则。因此修改方案不会改动已配好的规则，临时一次的时间也不会污染方案库。

## 数据模型

```swift
struct DaySchedule: Codable, Equatable {
    var start: String   // "HH:mm"
    var end: String
}
struct WorkSchedule: Codable, Equatable, Identifiable {
    var id: String
    var name: String
    var start: String
    var end: String
    var schedule: DaySchedule { DaySchedule(start, end) }  // 计算属性，不参与 Codable
}

// Prefs 新增（全部 decodeIfPresent，旧配置零影响）
var schedules:     [WorkSchedule]        = []   // 方案库
var weekdayRules:  [String: DaySchedule] = [:]  // "0"=日 ... "6"=六 → 作息值
var dateOverrides: [String: DaySchedule] = [:]  // "yyyy-MM-dd" → 当天作息值
// 现有 start / end 保留为「全局默认」，不迁移、不改名
```

## 优先级（纯函数 `schedule(for:_:)`）

```
当天日期覆盖 (dateOverrides)  >  星期规则 (weekdayRules)  >  全局默认 (start/end)
```

现有 `dayOverrides`（`yyyy-MM-dd` → 1 补班 / 0 放假）仍在 `isWorkday()` 里最优先决定「上不上班」，与本机制正交、不冲突：放假则不上班；补班则按当天解析出的作息上班。跨零点（`end <= start` 视为次日）在 `shifts(around:)` 里处理，对新作息一视同仁。

## 界面

「作息」Tab 新增三块，都是通用控件（不含任何预设时间）：

| 区块 | 内容 |
| --- | --- |
| 作息方案 | 列出已定义方案（名称 + 时间 + 删除）；内联表单添加（名称 + 上下班时间） |
| 每周规则 | 列出已配星期规则（星期 + 时间 + 删除）；内联表单添加（选星期 + 选方案 / 自定义时间） |
| 今天调整 | 显示当前生效的下班时间与来源；从方案选一个 / 自定义一次时间 / 恢复规则。只写当天日期，不影响模板 |

「作息方案」「每周规则」收进默认折叠的高级区（低频配置），「今天调整」常驻总览 Tab（每天用）；面板高度 480pt。

「上下班时间」（全局默认）、「工作日与午休」、「节假日 / 调休」保持原样。

## 典型用法

| 用户 | 配置 |
| --- | --- |
| 固定班 | 只填全局默认，行为与旧版完全一致 |
| 周五固定早收工 + 偶尔临时早下班 | 3 个方案 + 1 条「周五」星期规则；常规周零操作；临时那天用「今天调整」 |
| 轮班 | 给每个星期配不同规则 |
| 调休补班 | 现有「节假日 / 调休」功能照旧，补班日照当天规则计算 |

## 兼容与边界

- 旧配置没有 3 个新字段 → 解码为空，行为完全不变；现有 `start` / `end`、`workdays`、`dayOverrides` 不动。
- `validated()` 校验所有作息值的 `HH:mm` 合法性；非法值回落到全局默认。
- 日期覆盖只作用于键对应的那一天，不串到前后班次。
- 方案 / 规则数量不限，但 UI 用折叠表单避免一屏堆满（渐进式披露）。

## 验证

`--selftest` 覆盖：优先级链（日期 > 星期 > 默认）、空规则回落、跨零点、日期覆盖不串到明天、与补班 / 放假共存、`DaySchedule` Codable 往返。构建后验证三 Tab 渲染、方案增删、规则增删、今天调整与恢复、旧配置启动。
